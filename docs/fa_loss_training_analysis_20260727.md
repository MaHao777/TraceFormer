### 主要误差域

1. `val_023` 是当前最主要的召回瓶颈：
   - 占全部验证事件 27.48%，但占全部 FN 的 77.60%；
   - 只检出 `148/413` 个目标帧实例；
   - 去掉该文件做诊断性重算，整体 Score 从 `0.90719` 变为 `0.94978`。

2. `val_015` 是当前最主要的假警来源：
   - 产生 528 个事件 FP、396 个假警连通分量，均为单文件最高；
   - 去掉该文件做诊断性重算，整体 Fa 从 `8.870e-06` 变为
     `8.038e-06`，Score 变为 `0.90975`。

3. 同时去掉 `val_015` 和 `val_023` 时，诊断性 Score 为 `0.95439`。
   这不是可报告的比赛成绩，只说明剩余 22 个文件已经相对稳定。

4. `val_023` 并不是在“事件数、正例率、背景极性”三个简单统计上完全未见：
   `train_088` 有 399,750 个事件、1.385% 正事件、背景正极性率 0.539，
   与 `val_023` 的 391,344、1.531%、0.539 非常接近。失败更可能来自
   目标时空形态、尺度、运动轨迹或局部背景结构，而不是仅靠全局密度阈值即可解释。

## 模型参数分析

最佳模型共有 **102,874** 个可训练参数、100 个参数张量，无 NaN/Inf。
FP32 原始参数约 411,496 bytes，checkpoint 为 455,179 bytes。

| 模块 | 参数 | 占比 |
|---|---:|---:|
| Tokenizer | 40,800 | 39.66% |
| 3-layer cone encoder | 58,137 | 56.51% |
| Event decoder | 3,937 | 3.83% |

更细的主要参数来源：

| 子模块 | 参数 | 占比 |
|---|---:|---:|
| Encoder layers | 58,041 | 56.42% |
| Tokenizer query fusion | 20,736 | 20.16% |
| Token projection | 6,624 | 6.44% |
| Event encoder | 4,736 | 4.60% |
| Tokenizer K projection | 4,096 | 3.98% |
| Tokenizer V projection | 4,096 | 3.98% |
| Decoder classifier | 3,937 | 3.83% |

删除解码器重复的 4 个块统计后，第一层输入由 58 维降为
`48 token + 6 event-local = 54` 维，恰好减少 `4 * 48 = 192` 个参数；
模型从上一版记录的 103,066 降到 102,874。减少量不大，但去掉了编码器统计
到解码器的重复旁路。

四个 learned pool query 的两两余弦相似度非对角均值为 `0.132`，范围
`[-0.080, 0.352]`，说明 query 参数本身已经分化。query-fusion 对四个 query
输入块的权重范数占比分别为 24.91%、24.81%、25.23%、25.04%，没有明显弃用
某一个 query。该统计不能替代逐事件 attention 分布分析，但参数层面没有发现
query 塌缩或单分支独占。

## 验证 loss 记录方案

新实现从后续训练开始在每个 epoch 写入：

```json
{
  "train_loss": {
    "total": 0.0,
    "focal": 0.0,
    "dice": 0.0,
    "object_frame": 0.0,
    "false_alarm": 0.0
  },
  "validation_loss": {
    "total": 0.0,
    "focal": 0.0,
    "dice": 0.0,
    "object_frame": 0.0,
    "false_alarm": 0.0
  },
  "validation": {
    "threshold": 0.0,
    "competition": {},
    "event": {},
    "ev_uav_compatible": {}
  }
}
```

验证 loss 使用和训练相同的正样本保留、hard-negative 采样、密集序列权重与
完整事件 Fa 上下文；单独固定种子的验证 generator 保证跨 epoch 可比，且不会
改变训练采样顺序。`metrics.json` 继续只保存阈值指标，以保持独立复评协议清晰。
