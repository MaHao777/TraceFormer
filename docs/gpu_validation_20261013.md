# 2026-10-13 真实 GPU 推理验收

RTX 3090 上，冻结完整系统的全部 24 个测试序列各测三轮：同机 CPU 平均 **12.950 秒/序列**，完整 GPU 后端平均 **0.872 秒/序列**，提速 **14.85 倍**，耗时减少 **93.27%**。四个阶段的预测掩码、参考恢复掩码以及独立评分均保持一致。

本轮复用固定权重，执行真实推理、验证、测试和计时，没有重新训练或搜索阈值。所有代码在本地原仓库修改，保留原有未提交改动。

## 环境和计时方法

- GPU：NVIDIA GeForce RTX 3090，24GB；驱动 595.71.05。
- CPU：Intel Xeon Gold 6330，容器配额 14 vCPU；Torch 14 线程，CPU LightGBM 8 线程。
- PyTorch 2.8.0+cu128，CUDA 编译工具链 12.8.1，numba-cuda 0.30.4、Numba 0.68.0。
- NumPy 2.3.2、SciPy 1.17.1、LightGBM 4.7.0；FP32 网络，关闭 TF32，CUDA 确定性模式。
- 使用冻结 schema-5 主模型、schema-4 参考模型及发布 large 树；沿用原权重、归一化、阈值、事件顺序、float16 缓存量化和恢复规则。small 的融合权重为零，不参与预测。
- CPU 和完整 GPU 各三轮、每轮覆盖全部 24 个测试文件，共各 72 次测量；先用最大文件完整预热一次。数据、模型和冻结预测均经过 SHA256 校验。
- 从**内存输入归一化开始，到最终布尔掩码结束**计时，包括设备传输、稀疏视图、特征构造、树预测、CPU 跟踪和参考恢复。排除模型加载、首次 JIT、磁盘读取/写出、评分及一致性检查。CUDA 在计时边界同步。

主模型 SHA256：`9a361ac5319d5742bfb2ff4bc40de78ed9e17bb6061fa2afb255740515e4f184`；参考模型：`f92af958bde6114bc80e6a33e44524cf4e30d78ea34976b2fb75725f1d2ae9d0`。当前 schema-7 模型：`cb1bbdfad38d6a17c3a69e18e3091889243d97a5fe3dfbe945df23bf617b12ff`。权重没有改动。

## 正式全链路耗时

以下均为 24 个文件、每文件三轮平均，单位 **毫秒/序列**。各行互不重叠，合计为总时间；旧报告的 `verification_tracking_seconds` 是事件评分与跟踪的合计，不能再次加到总时间中。

| 阶段 | CPU | 完整 GPU 后端 | GPU 版运行位置 |
| --- | ---: | ---: | --- |
| 输入归一化及准备 | 2.434 | 1.886 | CPU + 上传 GPU |
| 网络、邻域、稀疏混合及 sigmoid | 6912.945 | 185.489 | GPU；几何分组及 KD-tree 准备仍在 CPU |
| 传回 CPU | 0.064 | 2.979 | GPU → CPU |
| 事件评分：量化、密度分组、特征及树 | 5414.550 | 138.954 | 主要在 GPU，含上下文准备和传输 |
| 事件分支及轨迹处理 | 595.938 | 518.439 | CPU |
| 参考 logits 阈值前处理 | 0.280 | 0.053 | 复用主模型 full logits |
| 参考轨迹恢复 | 23.907 | 24.060 | CPU |
| **总计** | **12950.117** | **871.861** | **14.85 倍** |

网络阶段提速约 37.27 倍，事件评分阶段约 38.97 倍。CPU 轨迹处理占 GPU 版总时间 **59.46%**，是下一步优化的主要瓶颈。这里的轨迹处理包括 `event_branches` 内部的掩码及轨迹逻辑。

最大事件数文件 `test_023.npz`（620,440 个事件）从 **77.707 秒降到 3.025 秒**，约 25.68 倍。GPU 单文件平均耗时的中位数为 0.680 秒，最慢文件平均 3.161 秒；因此不能用平均值承诺所有序列的固定延迟。

只指定 `--device cuda`、邻域/特征/树仍用 CPU 的路径另做**一轮诊断**：平均 10.654 秒，其中网络阶段 5.161 秒、事件评分 4.967 秒。该结果说明仅搬神经算子仍受 CPU 查询和后处理限制；正式速度比使用上述两组三轮结果。
