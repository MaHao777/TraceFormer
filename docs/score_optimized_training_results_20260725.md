# HUAV 官网分数优化训练结果（2026-07-25）

## 结论

本轮在 99 个训练文件、24 个验证文件上完成 6 个 epoch 的 CPU 全量训练。
最佳 checkpoint 来自 epoch 6，官网口径总分为 `0.895289886309`，相较
2026-07-24 基线的 `0.878893722080` 提升 `0.016396164230`。

改进主要来自目标级召回：`Pd` 从 `0.864762704746` 提升到
`0.925871482570`，多检出 291 个目标帧实例。`Fa` 从
`7.09270455194e-06` 上升到 `1.11664174838e-05`，但召回收益超过虚警代价，
最终官网加权总分提高。

## 改动

- 用序列极性均值、事件相对极性、Token 相对极性和极性熵减少绝对极性捷径。
- 锥邻居上限先按时间片内排名交错分配，使较远时间片不会被近邻全部挤掉。
- 背景采样保留一半最高 logit 的硬负样本。
- 加入目标帧 max-logit 召回损失，使每个目标帧至少出现一个高置信正事件。
- 对事件数不少于 300,000 且背景极性均值接近平衡的训练序列使用 3 倍权重。
- 使用 cosine 学习率衰减，并按完整官网评分而不是只按 IoU 选择阈值和 checkpoint。
- checkpoint schema 升级到 `3`，防止误加载旧 Token/解码器权重形状。

## 资源安全调整

最初的 `4×4` 空间块、128 时间块、4 层和每头 12 邻居配置在
`train_094.npz`（614,725 个事件）上生成 364,541 个 Token，Windows 事件日志
记录 `c10.dll` 访问冲突 `0xc0000005`。最小复现定位到超大稀疏注意力计算图，
不是数据文件损坏。

最终只收缩资源几何，改用 `8×8`、64 时间块、3 层和每头 8 邻居；同一文件生成
90,234 个 Token，完整 forward、loss 和 backward 均通过。失败产物没有删除，
保存在：

- `outputs/score_optimized_cpu_smoke_fine_grid_20260725/`
- `outputs/score_optimized_cpu_full_aborted_fine_grid_20260725/`

## 高密度域诊断

旧模型在 `val_023.npz` 上漏掉全部 5,990 个正事件和全部 413 个目标帧实例。
新模型在保存阈值 `0.95` 下得到：

- 正事件 `TP/FN = 966/5024`；
- 目标帧 `detected/objects = 135/413`，Pd 为 `0.326876513317`；
- 背景事件 `FP/TN = 973/384381`；
- 正事件概率中位数从不可检出状态提升到 `0.592434`，最大值为 `0.993735`。

该文件仍是当前主要短板，但已经从完全失效变成可检出，这与全局 Pd 的显著提升一致。
